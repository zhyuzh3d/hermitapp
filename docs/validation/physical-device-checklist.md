# Hermit v1 实体手机验收清单

请使用 Android 12 或以上的日常手机，并先把 Android System WebView/Chrome 更新到该系统可获得的最新版本。安装 `artifacts/v1.0.0/hermit-v1.0.0-release.apk` 后，在“诊断”中记录 Android 版本、WebView 版本和三项 Runtime feature；不要记录或发送设备序列号。

必须完成以下真实系统链路：

1. 冷安装后进入应用库；添加一个 HTTPS 页面与一个局域网 HTTP 页面，拒绝和允许局域网权限各验证一次。
2. 导入 `examples/voice-notes` 的 ZIP，保存文字，重启 Hermit 后确认仍存在；再从电脑连续部署两次，确认 appId、数据和桌面入口不变。
3. 分别验证朗读、语音识别的允许/拒绝/取消、近似与精确定位、系统相机取消与拍照、文件导入/导出、文本与文件分享、剪贴板读取授权、震动。
4. 为两个实例分别请求同一敏感能力，确认第二个实例仍出现独立 Hermit 授权；去系统设置撤销麦克风或定位后，调用必须失败且不能沿用旧系统状态。
5. 修改在线实例为不同 Origin，确认授权归零且需重新登录；同 Origin 只改路径则保持实例身份。
6. 导出含笔记与附件的备份，恢复为新实例，再用同一备份替换另一实例的数据；核对文字、附件、代码/地址保留规则与授权重置。
7. 固定桌面入口、重命名、启动、删除实例；确认旧入口不能重新访问数据。Launcher 若保留失效图标，记录厂商行为。
8. 在同一 Wi-Fi 上开启 LAN TLS 部署，分别验证正确 pin、错误 pin、Hermit 退后台和 15 分钟闲置；错误 pin 不得部署，退后台后端口应关闭。
9. 在系统深色模式、字体放大、横竖屏和 TalkBack 下走一遍添加、授权、备份与删除关键操作，确认没有不可达按钮或关键信息缺失。
10. 安装前保留已有 v0.9.0 同签名测试包数据时，用 `adb install -r` 或系统安装器覆盖到 v1.0.0；禁止先卸载，确认实例和数据仍在。

出现崩溃、数据丢失、越权、签名升级失败或无法恢复的主链阻断时，不应把该设备组合列为通过。系统服务缺失、厂商 Launcher 不支持固定快捷方式等环境限制应记录为“不支持/受限”，不能伪造成功。
