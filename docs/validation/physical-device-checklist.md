# Hermit v1 实体手机验收清单

请使用 Android 10 或以上的日常手机；可以把厂商 WebView 更新到当前可获得版本，但旧版本本身也应进入兼容测试。设备不要求安装 Google Play 服务或 Chrome。安装当前 release APK 后，在“诊断”中记录 Android 版本、WebView 包/版本、三项 Runtime feature 与 `runtimeMode`；不要记录或发送设备序列号。缺少 feature 的设备应继续验收页面主链，并把结果列为相应兼容模式，而不是“完整隔离模式”。

必须完成以下真实系统链路：

1. 冷安装后进入应用库；在无 GMS 且断开互联网的状态下扫描本地展示的 HTTP(S) 二维码，分别验证相机权限允许、拒绝、取消和无效二维码；结果只能预填表单，不能自动安装或发起外网请求。
2. 添加一个国内可达 HTTPS 页面与一个局域网 HTTP 页面，拒绝和允许局域网权限各验证一次；GitHub 不可达时其他添加方式必须正常。
3. 导入 `examples/voice-notes` 的 ZIP，保存文字，重启 Hermit 后确认仍存在；再从电脑连续部署两次，确认 appId、数据和桌面入口不变。
4. 分别验证原始麦克风录音（开始、停止、取消、时限、后台释放）和已保存音频的扬声器播放，再验证朗读、语音识别的允许/拒绝/取消、近似与精确定位、系统相机取消与拍照、文件导入/导出、文本与文件分享、剪贴板读取授权、震动；Android 10/11 不得调用 on-device 识别 API，Android 10 必须走定位兼容路径。
5. 为两个实例分别请求同一敏感能力，确认第二个实例仍出现独立 Hermit 授权；去系统设置撤销麦克风或定位后，调用必须失败且不能沿用旧系统状态。
6. 修改在线实例为不同 Origin，确认授权归零且需重新登录；同 Origin 只改路径则保持实例身份。
7. 导出含笔记与附件的备份，恢复为新实例，再用同一备份替换另一实例的数据；核对文字、附件、代码/地址保留规则与授权重置。
8. 固定桌面入口、重命名、启动、删除实例；确认旧入口不能重新访问数据。Launcher 若保留失效图标，记录厂商行为。
9. 在同一 Wi-Fi 上开启 LAN TLS 部署，分别验证正确 pin、错误 pin、Hermit 退后台和 15 分钟闲置；错误 pin 不得部署，退后台后端口应关闭。
10. 在系统深色模式、字体放大、横竖屏和 TalkBack 下走一遍添加、授权、备份与删除关键操作，确认没有不可达按钮或关键信息缺失。
11. 保留已有同签名正式包数据，用 `adb install -r` 或系统安装器覆盖到当前版本；禁止先卸载，确认实例和数据仍在。

出现崩溃、数据丢失、越权、签名升级失败或无法恢复的主链阻断时，不应把该设备组合列为通过。系统服务缺失、厂商 Launcher 不支持固定快捷方式等环境限制应记录为“不支持/受限”，不能伪造成功。
