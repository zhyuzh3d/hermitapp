# HermitApp 设备间 happ 分享开发计划

## 1. 目标与验收范围

本计划只建设 HermitApp 设备之间的 happ 代码包分享，不传输 happ 数据、Cookie、登录状态、Hermit Files、页面授权、通知配置或开发凭据。A 设备从应用卡片发起分享，B 设备使用 HermitApp 扫描二维码、确认 happ 信息并完成下载安装。

完成标准：

- A 可分享当前正式 release；当前运行开发副本时，分享点击瞬间锁定的开发 revision。
- 分享会话默认持续 1 小时，二维码内携带独立的六位数字分享密码，B 不需要输入密码。
- 二维码中央显示当前 happ 图标；没有图标时显示名称的第一个字符。
- B 扫码后先显示名称、版本、作者、包大小、正式版或开发快照、来源设备等信息；用户确认后才下载安装。
- 安装确认提供“创建桌面图标”开关，默认开启；安装成功后立即向 Android Launcher 请求固定快捷图标。
- A 可保存安装包、调用系统分享面板发送安装包，或主动停止分享。
- 没有可到达的局域网地址时仍生成 ZIP，但不启动下载服务，界面提示改用保存或系统分享。
- APK 构建、覆盖安装和真机启动完成；二维码分享入口、会话状态及安装合同通过直接相关检查。

## 2. 唯一产品流程

### 2.1 A 设备发起分享

应用卡片增加“分享”按钮。点击后 Native 读取实例当前启动通道：

- `stable`：锁定 `activeReleaseId`，从该不可变 release 生成 ZIP。
- `dev`：锁定当前 `devRevision`，从内容寻址开发树生成 ZIP；生成期间 revision 变化不会改变本次文件。
- 没有本地 release 的纯线上实时 happ：不伪造网站快照，明确提示当前 happ 没有可分享的本地安装包。

同一时间只保留一个活动分享会话。开始新分享会停止旧服务并清理旧临时文件。

### 2.2 分享弹窗

弹窗显示 happ 图标、名称、版本、包大小、分享类型、局域网状态、剩余有效期和二维码。二维码载荷只包含：

```text
hermit://share?v=1&u=<临时局域网服务地址>&p=<六位分享密码>
```

六位密码由 `SecureRandom` 每次生成，仅用于本次分享，不复用智能体开发密码，不要求 B 手工输入。二维码图像存为短期文件并通过 HermitUI 私有 URL 读取，不把 Base64 或图片字节写入数据库。

底部操作固定为：

- 保存安装包：使用 Android 文档创建器将当前 ZIP 写入用户选择的位置。
- 分享安装包：通过 `FileProvider` 和系统分享面板发送 ZIP。
- 停止分享：关闭服务、吊销密码并删除会话临时文件。

关闭弹窗不会停止分享；活动分享由前台服务维持，并显示系统通知。会话创建满 1 小时后自动停止。

### 2.3 B 设备扫码安装

Hermit 扫码器识别 `hermit://share` 后由 Native 解析，HermitUI 不接触六位密码。Native 使用二维码中的密码请求 A：

1. `GET /manifest` 读取小型分享描述。
2. HermitUI 显示安装确认和默认开启的“创建桌面图标”开关。
3. 用户点击安装后，Native 流式下载 `GET /package` 到临时文件。
4. 校验声明字节数与 SHA-256，然后调用现有 `InstallCoordinator` 完成 ZIP 校验、身份选择、不可变 release 写入和原子激活。
5. 开关开启时请求 Launcher 创建快捷图标；Launcher 仍可能显示系统确认或拒绝请求，界面必须如实返回结果。

扫码只消除手工输入地址、密码和选择 ZIP 的步骤，不能跳过安装确认。

## 3. 分享包与作者信息

ZIP 使用现有 happ 包格式，包根仍是直接可运行 Web 根，不引入第二种分享格式。

- 正式 release 原样保留其 `hermit.json`、图标及有效 `hermit.sig`。
- 开发副本没有修改时可保留原签名；开发树改变后移除不再匹配的 `hermit.sig`，但不阻止分享和安装。
- `author` 是可选展示信息，读取当前 `hermit.json`；开发副本默认继承原文件，只有用户或智能体明确编辑后才变化。
- 作者字段不等于密码学身份。B 的确认页分别显示作者与“正式版本 / 未签名开发快照”等状态，不能把失效签名描述成原作者认证。
- B 端 release 的来源记为 `device-share`；不复制 A 的实例 ID、本机来源绑定、数据或权限。

## 4. 临时服务与存储

分享文件位于 `cache/shared/happ-share/<sessionId>/`，包含 ZIP、二维码 PNG 和用于二维码中心的图标 PNG。数据库不新增文件内容或 Base64 字段，也不持久化分享密码。

临时 HTTP 服务只绑定当前可用的局域网接口并使用系统分配端口，只接受 `GET /manifest`、`GET /icon` 和 `GET /package`。所有接口要求 `Authorization: Bearer <六位密码>`；路径、查询参数和响应不回显密码。服务限制单个活动会话、固定文件、固定长度响应和有限并发，不提供目录列表、上传、任意路径或管理接口。

局域网地址沿用 Hermit 的 Wi-Fi、以太网和手机热点接口识别，排除蜂窝、VPN、回环和点对点接口。仅有移动数据时不发布服务地址，因为运营商 NAT 通常不可入站且不应把短密码服务暴露到公网。

一小时活动期通过显式的 Native 前台服务维持；停止、到期、APK 进程退出或应用被强制停止后会话立即失效。启动恢复不重建旧分享会话。

## 5. Native 与 HermitUI 合同

HermitUI 新增 Host 方法：

- `apps.shareStart({appId})`：创建包和会话，返回展示元数据、二维码私有 URL及局域网可用状态。
- `apps.shareSave({sessionId})`：选择目标文件并保存 ZIP。
- `apps.shareSend({sessionId})`：打开系统分享面板。
- `apps.shareStop({sessionId})`：停止当前会话。
- `apps.shareInstall({shareId, createShortcut})`：下载并安装已扫码确认的分享。

`apps.scanQr` 对普通 HTTP(S) 二维码保持现有添加网址行为；对 `hermit://share` 返回经过 Native 拉取和校验的安装描述以及短期 `shareId`，不把密码返回给页面。

HermitUI 增加两个弹窗：A 端分享弹窗和 B 端安装确认弹窗。应用卡片的分享按钮仅在存在本地代码时可用。

## 6. 失败与恢复

- ZIP 构建失败：不创建服务，保留原 release/dev workspace，显示具体错误。
- 网络不可用：保留本地包与保存/系统分享操作，不显示不可用二维码。
- 地址变化：当前二维码失效；用户重新点击分享生成新会话。
- 密码错误、过期或服务停止：B 显示“分享已失效，请重新扫码”。
- 下载中断或摘要不匹配：删除接收临时文件，不进入安装事务。
- 安装失败：不改变已有实例和 release 指针。
- 同 `happId` 冲突：复用现有安装身份确认，不静默覆盖其他实例。

## 7. 验证与部署

直接相关验证包括：

- Kotlin 编译及分享载荷、六位密码、过期、ZIP 摘要和二维码资产的单元/合同检查。
- HermitUI Host 白名单、卡片按钮、两个弹窗、开关和操作终态的静态合同检查。
- 正式 release 与开发 revision 均能生成可由 `InstallCoordinator` 接受的 ZIP。
- 无局域网时不会启动监听，仍可保存和系统分享。
- release APK 构建和签名校验；真机覆盖安装、版本核对、进程启动以及分享入口可调用。

不把 APK 安装成功误报为两台设备端到端验收；若现场只有一台 Hermit 设备，真机验收止于 A 端会话、二维码/导出及本机安装合同，双机扫码传输需第二台设备补充验证。
